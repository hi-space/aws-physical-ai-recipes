Date: 2026-09-18. Scope: `dashboard/web`. Branch `feat/hyperpod-dashboard`. Follows `2026-09-18-dashboard-factual-data.md` (same rules).

## Goal
A user who does not know the infrastructure must be able to see, on every page, which AWS resource the page reads and
through which API, see the whole Physical-AI-on-AWS architecture with live status on the home page, and perform the
HyperPod node operations (reboot / replace) safely from the Compute page.

## WP-C — HyperPod node operations from the Compute page (agent "nodes")
Files: `src/server/k8s/node-ops.ts` (+test), `src/server/services/node-recovery.ts` (+test), `src/app/api/clusters/[name]/nodes/[node]/recovery/route.ts`, `src/components/compute/NodeActions.tsx`, `src/components/pages/ComputePage.tsx`, `src/components/pages/ComputePage.browser.test.ts` (new), `src/components/pages/test-utils/storage-admin-browser.ts` (add `'compute'` entry only), `src/server/services/compute.ts` (+test) (add `nodeRecovery?: string` from DescribeCluster `NodeRecovery`), `src/lib/i18n/messages/compute.ts`.
- `node-ops.ts`: `getNode(name)`, `listPodsOnNode(name)` (fieldSelector `spec.nodeName=`), `setNodeHealthLabel(name, 'UnschedulablePendingReboot'|'UnschedulablePendingReplacement')` (PATCH merge-patch `{metadata:{labels:{...}}}`), `setCordon(name, boolean)` (PATCH `{spec:{unschedulable}}`). Node must carry `sagemaker.amazonaws.com/instance-group-name` (HyperPod node) or the call is rejected.
- `node-recovery.ts`: `planNodeRecovery(cluster, node, action)` → `{ observedAt, node: {name, instanceId?, group, health, ready, unschedulable, gpuCapacity}, cluster: {nodeRecovery}, pods: [{namespace, name, phase, owner?: 'daemonset'|'job'|…, workflowId?}], blockers: [{code, message}], warnings: [{code,message}], token }` where `token` is a hash of (node uid, health label, sorted pod uids) — the execute call must send it back and it is re-verified (409 `node_state_changed` otherwise). Blockers: `node_recovery_disabled` (cluster NodeRecovery !== 'Automatic'), `not_hyperpod_node`, `already_pending` (label already Unschedulable*). Warnings: `running_pods` (non-DaemonSet pods in non-system namespaces; list them). `executeNodeRecovery(cluster, node, action, token, acknowledgeRunningPods)` → verifies token, refuses when warnings include running_pods and not acknowledged (400 `ack_required`), applies the label, returns `{ appliedAt, label }`. Instance id: from `spec.providerID` (`aws:///az/i-…`) — extend the `Node` type with `spec.providerID?`.
- Route: `GET ?action=reboot|replace` → plan (admin); `POST { action, token, acknowledgeRunningPods }` → execute (admin, audit `node.recovery`). Cluster param must equal `config().eks.hyperPodClusterName`.
- UI: actions column in the Kubernetes nodes table (admin only): "재부팅"/"교체" buttons open `NodeActions` dialog: facts (node, instance id, group, health label, GPU, cluster NodeRecovery), pods table, blockers (red) / warnings (amber with checkbox acknowledgement), explanation of what happens ("라벨을 적용하면 SageMaker HyperPod 자동 노드 복구가 몇 분 내 노드를 재부팅/교체합니다. 노드의 Pod는 종료됩니다."), Execute button disabled until plan is current. After execution show the applied label and a note to watch the node's health label. Also show cluster `NodeRecovery` on the cluster card, and add the Compute `ResourceStrip` (hyperPodCluster console, eksCluster console, fsx console, clusterLogGroup).
- Tests: node-ops PATCH bodies; node-recovery blockers/warnings/token mismatch; browser test opens the dialog against fixtures and asserts blockers/warnings text and that Execute is disabled until acknowledged.
